Seção 2

Arquitetura Técnica

2.1 Visão Geral

O FarmaCC Pro é uma Single Page Application (SPA) totalmente client-side, com lógica de negócio no navegador e persistência de dados na nuvem via Firebase. 

Navegador (HTTPS)
  ├── HTML/CSS/JS (Firebase Hosting ou servidor local)
  ├── Firebase Authentication (login / controle de sessão)
  └── Firebase Realtime Database (dados em tempo real)
        ├── /users              → perfis de usuários
        ├── /medications        → estoque de medicamentos
        ├── /movements          → entradas, saídas, perdas, descartes
        ├── /surgeries          → procedimentos cirúrgicos
        ├── /residues           → descartes RDC 222/2018
        ├── /instruments        → instrumentais (RDC 15/2012)
        ├── /audit_log          → trilha de auditoria IMUTÁVEL
        └── /settings           → configurações institucionais + permissões

2.2 Módulos do Sistema

Módulo Funcionalidade Base Legal
Estoque CRUD de medicamentos com lote, validade, lista ANVISA Port. 344/98
Movimentações Saídas (com SNCR), entradas, devoluções, perdas, descartes Port. 344/98 Art. 58
Pacientes Registro de cirurgias vinculadas às dispensações RDC 204/2017
Resíduos Controle de MTR, empresa coletora, grupos B/D/E RDC 222/2018
Instrumentais Ciclos de reprocessamento, esterilização, limite do fabricante RDC 15/2012
Relatórios Balanço mensal + BSPO trimestral com assinatura do RT Port. 344/98 Art. 58 + Anexo XX

Infraestrutura e Banco de Dados (Firebase)

3.1 Firebase Realtime Database

O banco de dados utilizado é o Firebase Realtime Database, um banco NoSQL em tempo real hospedado pela Google Cloud Platform.

Característica Detalhe
Tipo NoSQL — JSON hierárquico sincronizado em tempo real
Provedor Google Firebase — Google LLC
Região dos dados us-central1 (Iowa, EUA) — dados armazenados em servidores Google
Criptografia em repouso Sim — AES-256 (padrão Google Cloud)
Criptografia em trânsito Sim — TLS 1.3 obrigatório
Certificações do provedor ISO 27001, ISO 27017, ISO 27018, SOC 1/2/3, PCI DSS
Conformidade com dados de saúde (EUA) HIPAA (mediante BAA com Google)
URL do banco https://farmacia-cc-default-rtdb.firebaseio.com
ID do Projeto Firebase farmacia-cc

3.2 Firebase Authentication

O controle de identidade dos usuários é gerenciado pelo Firebase Authentication, que autentica via e-mail/senha com tokens JWT.

Método de autenticação E-mail + senha (hash bcrypt no servidor Google)
Tokens JSON Web Token (JWT) — expiração automática em 1 hora, renovação automática
Senhas Nunca armazenadas em texto puro — hashing + salting no servidor Firebase
Proteção contra força bruta Bloqueio automático após 5 tentativas falhas (15 minutos)
Recuperação de senha Via e-mail com link temporário (Firebase email link)

3.3 Regras de Segurança do Banco

O acesso ao banco é controlado por Firebase Realtime Database Security Rules — regras declarativas avaliadas no servidor, antes de qualquer acesso.

✅
As regras de segurança garantem que mesmo que um atacante obtenha um token de acesso, ele só poderá ler/escrever os dados autorizados pelo seu perfil. A proteção funciona independentemente da camada de apresentação (front-end).

Resumo das regras implementadas:

  • /users — leitura permitida apenas para ADMIN e FARMACEUTICO_RT; cada usuário pode ler seu próprio perfil
  • /medications — leitura para todos os usuários ativos; escrita apenas para farmacêuticos e técnicos
  • /movements — leitura para todos; escrita para farmacêuticos, técnicos, médicos e enfermeiros; delete apenas para ADMIN/RT
  • /audit_log — leitura restrita; escrita somente com inserção (newData.exists() = true), deletar é proibido pelo banco
  • /settings — leitura geral; escrita apenas ADMIN/RT
Seção 4

Política de Retenção e Backup de Dados

⚠️
Exigência legal: A Portaria SVS/MS nº 344/98 Art. 58 determina que os registros de substâncias controladas devem ser conservados por no mínimo 5 (cinco) anos. O sistema está configurado para nunca deletar automaticamente registros de movimentações, auditoria e balanço.

4.1 Períodos de Retenção por Tipo de Dado

Coleção Tipo de dado Retenção mínima Base legal Status
/movements Movimentações de medicamentos 5 anos Port. 344/98 Art. 58 Nunca deletado automaticamente
/audit_log Trilha de auditoria 5 anos LGPD / RDC 204/2017 Imutável por regra do banco
/medications Cadastro de medicamentos Indefinido Port. 344/98 Mantido permanentemente
/residues Registros de descarte 5 anos RDC 222/2018 Art. 30 Mantido permanentemente
/surgeries Procedimentos cirúrgicos 20 anos CFM / Lei 8.159/91 Mantido permanentemente
/instruments Instrumentais e ciclos 5 anos RDC 15/2012 Mantido permanentemente
/users Perfis de usuários Enquanto vigente + 2 anos LGPD Art. 16 Gerenciado pelo RT

4.2 Backup de Dados

ℹ️
O Firebase Realtime Database realiza backup automático interno gerenciado pela Google. Os dados são replicados em múltiplos data centers geograficamente distribuídos (alta disponibilidade). Adicionalmente, a instituição deve realizar backups periódicos conforme política abaixo.
Tipo de Backup Frequência Responsável Formato Retenção
Backup Google (automático) Contínuo (replicação em tempo real) Google LLC (Firebase) Interno — não acessível diretamente Conforme SLA Google
Export manual Recomendado: mensal ADMIN / Farmacêutico RT JSON (Firebase Console → Export) Mínimo 5 anos (HD externo / nuvem)
Export CSV por módulo Recomendado: ao gerar relatório mensal Farmacêutico RT CSV (botão Exportar em cada módulo) Arquivo físico: 5 anos
Impressão de relatórios Mensal (balanço) / Trimestral (BSPO) Farmacêutico RT PDF / Papel (assinado) 5 anos em arquivo físico

4.3 Procedimento de Export Manual (Firebase Console)

  1. Acesse console.firebase.google.com
  2. Selecione o projeto farmacia-cc
  3. Navegue para Realtime Database → Data
  4. Clique no ícone de ⋮ (três pontos) → Export JSON
  5. Salve o arquivo com nomenclatura: backup_farmacc_AAAAMM.json
  6. Armazene em local seguro com controle de acesso

4.4 Recuperação de Dados (Disaster Recovery)

Em caso de perda de acesso ou exclusão acidental de dados:

  • Firebase suporta restauração via arquivo JSON exportado anteriormente
  • Dados deletados por erro podem ser recuperados via suporte Google (ponto-in-time recovery disponível no plano Blaze)
  • O audit_log é protegido contra deleção por regra de banco — garantia adicional de integridade

5.1 Trilha de Auditoria (audit_log)

Todo evento sensível no sistema gera automaticamente um registro imutável em /audit_log.

Campo Descrição Exemplo

action Tipo de ação realizada MOVEMENT_SAIDA
module Módulo onde a ação ocorreu movements
recordId ID do registro afetado -NxYz123...
details Descrição detalhada da ação Saída: 2x Fentanila (A1). Protocolo: SAI-20260702-001

5.3 Imutabilidade dos Registros

🔒
audit_log é tecnicamente imutável: A regra de segurança do Firebase proíbe qualquer operação de deleção ou atualização nesta coleção. A regra implementada é: ".write": "auth != null && newData.exists()" — só permite inserção (quando o novo dado existe), nunca deleção (newData.exists() = false). Isso garante integridade da trilha mesmo que um usuário com acesso administrativo ao console tente apagar registros.

5.4 Rastreabilidade de Medicamentos Controlados

O sistema implementa rastreabilidade completa da cadeia de custódia: 

Medicamento cadastrado (lote + validade obrigatórios para listas A/B)
  ↓
Entrada registrada (NF + fornecedor)
  ↓
Cirurgia/paciente registrado (prontuário, cirurgião, anestesista)
  ↓
Saída dispensada (SNCR/Notificação obrigatório para listas A1/A2/A3/B1/B2)
  ↓
Auditoria gerada automaticamente (usuário + timestamp + detalhes)
  ↓
Relatório de Balanço / BSPO disponível para impressão (assinatura RT)
Seção 6

Controle de Acesso e Autenticação

6.1 Perfis de Usuário

Perfil Descrição Nível de Acesso
Administrador (ADMIN) Desenvolvedor / gestor do sistema Total — inclui gerenciar usuários e permissões
Farmacêutico RT Responsável Técnico pela farmácia Total — único que emite balanço e assina relatórios
Farmacêutico Farmacêutico auxiliar Operacional + relatórios (sem gerenciar usuários)
Técnico em Farmácia Técnico de nível médio Operacional (sem excluir)
Médico / Anestesista Médico que solicita medicamentos Consulta estoque + registrar saída
Enfermeiro RT Enfermeiro responsável no CC Operacional completo (sem excluir)
Gestor Gestor hospitalar Somente leitura e relatórios

6.2 Princípio do Menor Privilégio

O sistema implementa o princípio do menor privilégio: cada usuário tem acesso apenas às funcionalidades necessárias para seu papel. As permissões são verificadas em duas camadas:

  • Camada 1 — Front-end: Botões e menus são ocultados para usuários sem permissão
  • Camada 2 — Firebase Rules (servidor): Mesmo que o front-end seja bypassado, o servidor rejeita a operação

6.3 Proteção contra Acesso Não Autorizado

Sessão inativa Timer de inatividade: logout automático após período configurável
Tentativas de login Bloqueio após 5 tentativas incorretas (15 minutos)
Tokens JWT Expiração automática a cada 1 hora (renovação transparente)
HTTPS obrigatório Toda comunicação é criptografada (TLS 1.3)
Código de bypass removido Nenhum bypass de autenticação no código de produção
Seção 7

Conformidade Regulatória — Perguntas Frequentes da VISA

Esta seção responde objetivamente às perguntas mais comuns feitas por fiscais da Vigilância Sanitária durante inspeções de farmácias hospitalares.

7.1 Perguntas sobre Controle de Substâncias (Port. 344/98)

Pergunta da Fiscalização Resposta / Evidência no Sistema
O sistema diferencia medicamentos controlados dos demais? ✅ Sim. Campo Lista obrigatório: A1, A2, A3, B1, B2, C1-C5, D1 ou Não Controlado. Badges visuais distintos em toda a interface.
Como é registrada a saída de um controlado? ✅ Cada saída exige: medicamento, quantidade, paciente, prontuário, médico, CRM e Nº de Notificação/SNCR obrigatório para listas A1/A2/A3/B1/B2 (RDC 873/2024).
O sistema impede a saída de medicamento vencido? ✅ Sim. O sistema verifica a validade no momento do registro. Se o medicamento estiver vencido, a saída é bloqueada com mensagem de erro citando Port. 344/98 Art. 57.
Os registros de movimentação podem ser alterados? ✅ Não. Movimentações são imutáveis. Qualquer cancelamento é registrado como cancelamento lógico (status: cancelado) com motivo e responsável — o registro original permanece.
Como é gerado o Balanço Mensal (Art. 58)? ✅ Menu Relatórios → Balanço Mensal. Gerado automaticamente com entradas, saídas, perdas e saldo por substância. Disponível para impressão com campo de assinatura do RT.
O sistema gera o BSPO Trimestral? ✅ Sim. Menu Relatórios → BSPO Trimestral. Selecionar T1/T2/T3/T4 + ano. Inclui prazo legal de entrega e campos de assinatura.
Há registro de desvios/roubos? ✅ Sim. Campo causa = desvio/roubo no registro de perda. O sistema exibe alerta obrigatório ao RT e cria registro especial ALERT_DESVIO_CONTROLADO no audit_log.

7.2 Perguntas sobre Resíduos (RDC 222/2018)

Pergunta da Fiscalização Resposta / Evidência no Sistema
Há registro de descarte de resíduos farmacêuticos? ✅ Módulo Resíduos com campos: data, grupo (B/D/E), descrição, quantidade, empresa coletora e MTR.
O MTR (Manifesto de Transporte) é registrado? ✅ Sim. Campo Número MTR obrigatório para descartes. Ausência de MTR é sinalizada no módulo de Conformidade.
Há verificação da empresa coletora? ✅ Campos: razão social, CNPJ (com validação de formato) e licença IBAMA.

7.3 Perguntas sobre Reprocessamento (RDC 15/2012)

Pergunta da Fiscalização Resposta / Evidência no Sistema
O sistema controla o número de reprocessamentos? ✅ Módulo Instrumentais com campo Ciclos Realizados / Ciclos Máximos. Barra de progresso visual. Alerta automático ao atingir limite do fabricante.
Há registro de esterilização? ✅ Cada ciclo registra: data, método (autoclave, ETO, plasma H₂O₂, etc.) e responsável.
Como é tratado o instrumental que atingiu o limite? ✅ O sistema muda o status para Descartado automaticamente ao atingir o limite e exibe alerta ao usuário.

7.4 Perguntas sobre Auditoria e LGPD

Pergunta da Fiscalização Resposta / Evidência no Sistema
O sistema registra quem fez cada ação? ✅ Toda ação sensível é auditada com: UID do usuário, nome, perfil, data/hora (servidor), módulo, ID do registro e detalhes.
Os logs de auditoria podem ser alterados? ✅ Não. A coleção audit_log tem regra de banco que proíbe deleção e atualização por qualquer usuário, incluindo administradores.
Por quanto tempo os logs são mantidos? ✅ Indefinidamente no banco (sem deleção automática). Política recomendada: 5 anos conforme Port. 344/98. Exportação CSV disponível para arquivo histórico.
Dados de pacientes são protegidos (LGPD)? ✅ Acesso restrito por perfil. Dados criptografados em trânsito e em repouso. Sem exposição em URLs. Consentimento implícito pelo uso do prontuário hospitalar.

Seção 9

Procedimentos de Emergência e Contingência

9.1 Falha de Conexão com Internet

⚠️
O Firebase Realtime Database mantém cache local no navegador para leitura dos últimos dados carregados. Porém, novas escritas (registros de saída, entrada) requerem conexão. Em caso de falha, use o Registro Manual em papel e lance no sistema quando a conexão for restabelecida.

Plano de contingência recomendado:

  1. Manter bloco de formulários físicos de registro de dispensação
  2. Ao retornar a conectividade, lançar todas as movimentações no sistema na sequência correta
  3. Registrar no campo Justificativa a data/hora real e o motivo do lançamento retroativo

9.2 Acesso de Emergência ao Console Firebase

Em caso de necessidade de recuperação de dados ou acesso administrativo direto ao banco:

  • URL: console.firebase.google.com
  • Projeto: farmacia-cc
  • Acesso: conta Google vinculada ao projeto (responsabilidade do Admin)
  • Nunca compartilhar credenciais do console com usuários do sistema

9.3 Suspensão do Sistema

Antes de suspender o uso do sistema, o Farmacêutico RT deve:

  1. Exportar backup completo JSON do Firebase Console
  2. Gerar e imprimir todos os Balanços Mensais e BSPO pendentes
  3. Desativar todos os usuários ativos (módulo Usuários)
  4. Guardar os arquivos exportados por no mínimo 5 anos
